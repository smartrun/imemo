# iMemo 구현 계획 v2: HTML 에디터 → 가로형 전용 코드 이미지 → macOS(SwiftUI) 복원

## 1. 확정 요구사항
| 항목 | 결정 |
|---|---|
| 문서 | 텍스트 위주, 수 KB 이내. HTML 서식(굵게/제목/목록/표) 유지. 이미지·첨부 제외 |
| 출력 | 가로로 긴 직사각형 코드 이미지를 **HTML 페이지 안에 직접 표시**(canvas, 파일 저장 없음). **가로폭은 사용자가 선택** (모니터 가로 해상도 이하) |
| 실행 환경 | 생성 측은 **클라우드 PC**. 화면 해상도 변경, 스케일링, 프레임 드롭, 화면 압축이 있을 수 있음 |
| 보안 | 비밀번호 없음. **비표준 포맷**으로 이 프로그램에서만 인식 (난독화 수준, 암호학적 보안 아님) |
| 읽기 앱 | SwiftUI macOS 앱, **macOS 26 이상**. 입력은 **원격 클라우드 화면의 특정 영역 캡처**(주 경로), 이미지 파일 열기는 보조 |
| 대용량 | 한 장에 안 들어가면 **슬라이드(애니메이션) 모드**: 여러 프레임을 순환 표시하고 맥이 연속 캡처해 합침 |
| 색상 | **2/4/8/16색** 중 옵션 선택 (기본 2색 흑백) |

## 2. 핵심 설계 변경: 표준 QR → 자체 매트릭스 코드("IMC")
클라우드 PC에서 화면을 캡처하면 리사이즈, 블러, JPEG/비디오 압축이 생깁니다. 표준 QR 여러 개는 작은 모듈이 뭉개지기 쉽고 비표준 요구도 맞지 않습니다. 그래서 다음과 같이 설계합니다.

- **흑백 1비트 셀 격자**: 색상 대신 명암만 사용합니다. 압축과 색 왜곡에 강합니다.
- **큰 셀**: 셀 한 칸은 기본 6~8px입니다. 사용자가 고른 가로폭에 맞춰 셀 크기를 자동으로 정합니다 (정수 px).
- **Reed-Solomon 오류정정(GF(256))**: 손상과 프레임 깨짐에 대비해 패리티를 25~35% 넣습니다. 블록은 인터리브해서 가로 방향 번짐을 분산합니다.
- **위치 인식 패턴**: 외곽 굵은 테두리, 4개 모서리의 비대칭 파인더, 상단·좌측의 교차 타이밍 패턴(흑백 교대)을 둡니다. 스케일이 바뀌어도 셀 크기와 격자를 복원할 수 있습니다.
- **비표준 처리**:
  - 매직 헤더는 고정 비트열이 아닌 키 스트림으로 가립니다.
  - 데이터 전체를 앱 내장 시드의 PRNG 키 스트림(XOR)으로 스크램블합니다.
  - 셀 배치 순서는 시드 기반 순열로 섞습니다.
  - 일반 QR 리더는 인식하지 못합니다.
- **무결성**: 전체 CRC32를 넣고, 불일치하면 복원을 거부합니다.
- **가로 직사각형**: 데이터 크기와 선택한 가로폭으로 열 수를 정하고, 행 수는 비율(약 4:1~8:1)에 맞게 계산합니다. 필요하면 블록 여러 개를 가로로 이어 붙입니다.

### 용량 추정
가로 1920px, 셀 6px이면 약 300열입니다. 행이 40이면 12,000셀이므로 약 1.5KB입니다. 패리티 30%를 빼면 약 1KB의 유효 데이터가 들어갑니다.
A4 한 장 텍스트는 압축 후 2~4KB 정도이므로, 높이를 늘려 약 8~16:1 비율로 맞추거나 블록을 2~3단으로 쌓습니다.
"가로로 긴 형태"를 유지하려면 가로폭이 클수록 유리합니다. 생성 시 예상 용량과 비율을 UI에 표시하고, 초과하면 경고합니다.

## 3. 데이터 파이프라인
```
HTML → sanitize(허용 태그 화이트리스트) → UTF-8 → zlib 압축
→ 헤더(버전, 길이, CRC32) 부착 → RS 인코딩 → 인터리브 → XOR 스크램블
→ 시드 순열 배치 → 셀 격자 + 파인더/타이밍 → 선택 폭에 맞춰 에디터 아래 canvas에 즉시 표시
```
복원은 정확히 역순입니다.

## 4. HTML 측 (단일 `index.html`, 오프라인 동작)
- 에디터: `contenteditable` + 툴바(굵게, 제목, 목록, 표 삽입)
- 하단 **"이미지"** 버튼, **가로폭 선택**(드롭다운: 현재 화면 가로폭 `screen.width`, 1920, 1600, 1280 등, 모니터 가로 해상도 이하로 제한), 예상 용량·비율 표시
- 클라우드 PC 대응:
  - 이미지는 `devicePixelRatio`와 무관하게 **정수 px 셀**로 그려 흐림을 막습니다.
  - 화면에 보여줄 때는 `image-rendering: pixelated`로 100% 표시하고 확대·축소를 비활성화합니다.
  - 파일 저장은 하지 않고, 화면 표시용 보조 기능으로 "전체화면 확대 표시"(정수 배율, 닫기 버튼)만 둡니다.
- 모든 로직은 의존성 없이 직접 구현합니다 (RS, CRC, PRNG, 압축은 `CompressionStream('deflate')` 사용, 미지원 시 내장 소형 deflate 폴백).

## 5. SwiftUI 앱 (`ImemoReader`, macOS 26+)
- UI: 이미지 드롭 영역, 파일 열기, 결과 `WKWebView`(sanitize 후 렌더), 복사, HTML/텍스트 저장, 오류·품질 표시
- 디코딩 (Vision/CoreImage는 보조로만 사용, 핵심은 자체 구현):
  1. 이미지를 그레이스케일로 변환하고 적응형 임계값으로 이진화합니다.
  2. 외곽 테두리와 파인더를 찾아 코드 영역을 검출합니다.
  3. 타이밍 패턴으로 셀 크기와 격자를 추정합니다. 스케일 변경, 소폭의 가로·세로 비율 차이를 보정합니다.
  4. 각 셀 중앙의 주변 평균으로 비트를 샘플링합니다.
  5. 역순열, 역스크램블, RS 디코딩, CRC 검증, zlib 해제를 거쳐 HTML로 복원합니다.
- RS 디코더는 소실과 오류 모두 처리합니다. 실패하면 이진화 임계값과 샘플링 오프셋을 바꿔 재시도합니다.
- 모듈 구성: `ImageBinarizer`, `GridLocator`, `CellSampler`, `ReedSolomon`, `Scrambler`, `Container`, `HTMLSanitizer`, `ContentView`

## 6. 마일스톤
1. 포맷 명세 확정 + 테스트 벡터 작성(JS/Swift 공통)
2. JS 인코더, `index.html` 에디터 UI 완성
3. Swift 디코더 코어(RS, 격자 검출) + 단위 테스트
4. SwiftUI 앱 UI 통합
5. 열화 테스트: 50~150% 리사이즈, JPEG 품질 50, 가우시안 블러, 약간의 노이즈 후 복원율 확인
6. 보강: 오류 메시지, 품질 지표, 문서화

## 8. 추가 확정 기능 (v3)

### 8.1 화면 영역 캡처 (맥)
- **ScreenCaptureKit** 사용 (`SCStream`, 단발은 `SCScreenshotManager`). 최초 실행 시 화면 기록 권한 안내 필요.
- 영역 지정: 전체화면 투명 오버레이 창에서 드래그로 사각형을 선택하고, 선택 영역을 저장해 다음 실행에도 재사용. 단축키로 "캡처 시작/중지".
- 캡처는 픽셀 정확도가 중요하므로 Retina 네이티브 해상도로 받고, 원격 데스크톱 창이 축소 표시되는 경우를 가정해 타이밍 패턴으로 셀 크기를 재추정.
- 단발 모드(정지 이미지 1장)와 연속 모드(슬라이드)를 모두 지원.

### 8.2 슬라이드 모드 (대용량)
- HTML 쪽: 데이터가 한 프레임 용량(선택 가로폭 기준)을 넘으면 자동으로 N프레임으로 분할해 일정 간격(기본 500ms~1s, 조절 가능)으로 순환 재생. 시작·끝 구분 프레임, "n/N" 사람이 읽는 표시, 일시정지 버튼.
- 프레임 헤더: 문서 ID, 프레임 번호, 전체 프레임 수, 전체 CRC.
- **프레임 간 소실 복구**: 프레임 드롭에 대비해 순환 재생 + 패리티 프레임(XOR 또는 RS 소거 코드) 추가. 전체 N개 중 일부를 못 받아도 복원 가능.
- 프레임 전환 중 캡처되는 찢어짐은 프레임별 RS+CRC로 걸러내고 폐기.
- Swift 쪽: 연속 캡처 → 프레임별 디코드 → 수집 상태 UI(받은 프레임 n/N 체크 표시) → 모두 모이면 자동 복원. 같은 프레임은 중복 무시.
- 한 프레임에는 문서 ID로 구분해 다른 문서와 섞이는 것을 방지.

### 8.3 컬러 옵션 (2/4/8/16색)
- 셀당 1/2/3/4비트. 같은 면적에서 용량이 최대 4배.
- 팔레트: 대비가 큰 고정 팔레트 (예: 4색=흑/백/빨강/파랑 계열). 비표준 요건에 맞춰 팔레트 순서도 시드로 섞음.
- **색 보정**: 원격 화면은 색이 변질되므로 각 프레임의 모서리·헤더에 **전체 팔레트 기준 셀**을 넣고, 읽을 때 그 값을 기준으로 가장 가까운 색(Lab 거리)으로 분류.
- 색 수가 많을수록 인식률이 떨어지므로 RS 패리티를 자동으로 증가 (2색 25% → 16색 40%).
- UI에 "색 수 ↔ 용량 ↔ 안정성" 가이드를 표시. 기본은 2색.

## 13. 구현 완료 내역 (v4 - 2026-11-02)

1. **클라우드 PC용 단일 파일 웹 에디터 (`web/index.html`)**:
   - WYSIWYG 서식 툴바 (제목 H1~H3, 굵게, 기울임, 밑줄, 취소선, 글머리/번호 목록, 표 삽입, 서식 지우기).
   - 가로폭 설정 (화면 맞춤, 800~1920px 및 사용자 지정), 셀 크기(6~12px), 색상 옵션(2, 4, 8, 16컬러), 슬라이드 간격(400~1500ms).
   - "이미지 생성 (IMC 코드)" 버튼 클릭 시 페이지 내 canvas에 가로형 비표준 매트릭스 바코드 렌더링 (파일 저장 없음).
   - 슬라이드 모드: 대용량 문서는 자동 분할 + 25% XOR 패리티 복구 프레임 추가 + 순환 애니메이션 재생 + 전체화면 확대 보기.
   - 외부 의존성 없는 100% 오프라인 동작.

2. **macOS 26+ (27.0.1) 리더기 (`ImemoReader/ImemoReader.app`)**:
   - 최신 `ScreenCaptureKit` 기반 250ms 고속 연속 영역 캡처.
   - 마우스 드래그로 캡처 영역을 지정하는 반투명 오버레이 창 (`RegionSelector`) 및 선택 영역 자동 저장.
   - 바코드 테두리 자동 감지, 타이밍 패턴/셀 크기 추정, 실시간 기준 팔레트 캘리브레이션.
   - 비표준 키스트림 역스크램블, GF(256) 멀티블록 인터리브 Reed-Solomon 오류정정, CRC32 검증.
   - 슬라이드 프레임 수집기: 원격 전송 중 프레임 드롭(누락) 발생 시 XOR 패리티로 자동 복구.
   - raw DEFLATE / zlib 압축 해제 후 `WKWebView` 서식 렌더링 및 HTML/텍스트 복사, 파일 저장.
   - 이미지 파일 드래그앤드롭 및 파일 열기 보조 지원.

3. **엔드투엔드 검증**:
